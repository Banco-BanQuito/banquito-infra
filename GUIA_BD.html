Setup General — Todos hacen esto una vez

  1. Instalar Docker Desktop

    Descargalo de docker.com/products/docker-desktop e inícialo. Verifica que esté corriendo (icono de ballena en la barra).

  2. Clonar banquito-infra

    git clone https://github.com/Banco-BanQuito/banquito-infra.git
cd banquito-infra

  3. Levantar las bases de datos y RabbitMQ

    Este comando levanta PostgreSQL, MongoDB y RabbitMQ. Las tablas y datos se crean solos (tarda ~1 minuto la primera vez).

    docker-compose up -d postgres mongo rabbitmq

    Verificar que todo esté verde:

    docker-compose ps

  4. Copiar tu application.properties

    En la carpeta templates/ del repo está el archivo listo para tu servicio. Cópialo a src/main/resources/application.properties.

    QuiénArchivo en templates/
    Oscarapplication-oscar.properties
    Bryanapplication-bryan.properties
    Santiagoapplication-santiago.properties
    Alanapplication-alan.properties
    Paulapplication-paul.properties
    Johan (tariff)application-johan-tariff.properties
    Johan (clearing)application-johan-clearing.properties
    Anthony (report)application-anthony-report.properties
    Anthony (notif)application-anthony-notification.properties

  5. Correr tu servicio desde IntelliJ

    Dale Run a tu @SpringBootApplication. Hibernate crea las tablas automáticamente. Para Spring Data MongoDB las colecciones se crean solas.

    ℹ️ El application.properties ya tiene localhost:5432 por defecto para pruebas locales. Cuando corras dentro de Docker, el docker-compose inyecta la URL correcta automáticamente.

  6. Probar con Postman o curl

    Instala Postman (gratuito) o usa curl desde la terminal. Usa los ejemplos de la sección de tu nombre más abajo.

⚠️ Si ya levantaste Docker antes sin las tablas: corre docker-compose down -v para borrar todo y luego docker-compose up -d postgres mongo rabbitmq de nuevo para que los scripts corran desde cero.

Flujo que Paul implementa

1. Consumir RabbitMQ cola: payment.lines.queue
2. Por cada mensaje:
   - routingCode == "001" → POST http://localhost:8000/api/v2/payments/batch-credit (Oscar vía Kong)
   - routingCode == "002","010",... → publicar en clearing.outbound.queue (Johan lo consume)
3. Cuando lote completo:
   - GET http://localhost:8086/api/v2/tariff/calculate?successful_tx=N (Johan tariff)
   - POST http://localhost:8000/api/v2/payments/corporate-debit (Oscar vía Kong)
ℹ️Para probar el flujo completo necesitas que Oscar (:8081), Johan tariff (:8086) y Kong (:8000) estén corriendo. Puedes probar el consumo de cola de forma aislada mockeando las llamadas HTTP salientes.
